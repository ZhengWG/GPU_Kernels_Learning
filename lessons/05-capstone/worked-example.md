# 综合作业示例：两行 RMSNorm

**一份无 GPU 报告也应把接口、数据分工、正确性和待测项写完整。** 前置：[归一化](../02-hardware-and-profiling/normalization.md)、[资源预算](../../docs/hardware/resource-budget.md)。下面是教学设计，不是已验证的 CUDA 方案。

## 输入与结果

输入 x 为连续 FP32 的 `[2,33]`，gamma 为连续 `[33]`，输出 y 为独立连续 `[2,33]`；所有输入有限，epsilon 显式设为 1e-5，按最后一维归一化，无偏置。先限定小幅值教学输入，不宣称任意有限 FP32 的平方都不会溢出。

```text
y[i,j] = x[i,j] / sqrt(sum_k(x[i,k]^2)/33 + 1e-5) * gamma[j]
```

CPU 参考用 Decimal 或 Python 双精度，实际 GPU 候选采用 FP32 累加并写 FP32。比较既检查绝对误差也检查相对误差；阈值应针对输入范围与库基线确认，不用“看起来接近”替代检查。

## 分工与搬运图

```text
原理示意：每行先尝试交给一个 warp
线程位置  0       1       2      ... 31
负责列    0,32    1       2      ... 31

读取自己负责的 x → 局部平方和 → 合并整行平方和
          保留 x ─────────────→ 算输出并连续写回
```

有效元素数是 33，不是补齐后的 64。每个有效输出恰好有一个写入者；所有参与归约的线程按相同范围协作。只有两行，意味着只安排很少的工作，这个例子适合解释索引，不用于承诺高吞吐。

## 两个候选与成本

| 候选 | 逻辑流量，忽略统计量 | 可能收益 | 代价 |
| --- | --- | --- | --- |
| 统计后重读 x | x 两遍、gamma 一遍、y 一遍：1056 字节 | 少保留输入 | 多读 264 字节 |
| 在线程中保留 x | x、gamma、y 各一遍：792 字节 | 减少 x 重读 | 增加寄存器存活值 |

这里 gamma 按每行逻辑访问计数；缓存可能复用它。字节数不是实测 HBM 流量。行内平方、加和、输出两次乘法约为每行 `4D-1` 次普通算术操作，另外统计均值、加 epsilon、求倒数平方根；不能把所有指令统一按 Tensor Core 峰值估算。

## 正确性清单与答案要点

- D=1：输出一般不等于 x，也不恒为零，必须按公式算。
- 全零行：结果为零，不出现除零。
- 常数非零行：RMSNorm 不减均值，不能误写成 LayerNorm。
- D=33：第二轮只有第 0 个线程有新元素，无效位置不增加计数。
- gamma 不是全 1：检查逐列缩放，防止遗漏参数。

[check_classic_operators.py](../../tools/check_classic_operators.py) 已覆盖这些数值与尾部情形；它没有检查真实 warp 交换或 GPU 寄存器分配。

## 结论怎样写

“保留 x 在本教学计数下减少一次输入读取；正确性数学参考已通过。能否提升 H20 性能未测量，需检查实际资源、增加代表性行数和行宽，再用相同计时范围与库基线比较。”

这份结论区分了已证明的访问量变化和待验证的速度变化，满足当前理论作业要求。
