# 张量与内存布局：形状不是存储顺序

**写 kernel 时，既要知道有几行几列，也要知道相邻元素隔多远。**

## 二维数组放在一段内存中

```text
原理示意

逻辑矩阵 A，shape = (2, 3)       连续存储，stride = (3, 1)
       列 0  1  2
行 0     0  1  2                [0][1][2][3][4][5]
行 1     3  4  5                 └─行 0─┘└─行 1─┘

A[1, 2] → 1 × 3 + 2 × 1 = 第 5 个偏移 → 值为 5
```

`shape` 是每一维有多少元素；`stride` 是该维索引增加 1 时，要跨过多少个元素。这里跨一行走 3 格，跨一列走 1 格。

对于二维视图，从底层存储起点计算：

```text
元素偏移 = storage_offset + 行索引 × 行步长 + 列索引 × 列步长
字节偏移 = 元素偏移 × 每个元素的字节数
```

如果传给 kernel 的指针已经是视图首元素地址，就不要再加一次 `storage_offset`。

## 转置可以只改变解释方式

```text
原理示意：A.T 与 A 共用同一段存储

A: shape (2,3), stride (3,1)      A.T: shape (3,2), stride (1,3)
        0 1 2                             0 3
        3 4 5                             1 4
                                          2 5

底层仍是 [0][1][2][3][4][5]，没有重新排成 [0][3][1][4][2][5]。
```

PyTorch 的转置通常产生共享存储的视图。`.contiguous()` 在需要时复制成连续布局；`reshape()` 可能返回视图，也可能复制，不能默认没有搬运开销。[PyTorch Tensor Views](https://docs.pytorch.org/docs/main/tensor_view.html)

## 广播也不意味着复制

给 `(2, 3)` 矩阵加一个 `(3,)` 向量时，两行都使用同一行偏置。kernel 可以反复读取同一个偏置元素，不必先生成两份。展开视图可能有步长为 0 的维度，因此不能假定不同逻辑索引一定指向不同地址。

| 写 kernel 前检查 | 漏掉后的常见问题 |
| --- | --- |
| shape / dtype / device | 处理了错误尺寸、类型或设备 |
| stride / 是否连续 | 转置输入结果错误 |
| 起点与对齐 | 切片输入不满足向量化读写要求 |
| 输出是否和输入共用存储 | 写入覆盖了尚未读取的数据 |

首个实验可以只支持连续输入，但必须明确检查或声明限制。

## 自测

在上图中，`A.T[2, 1]` 位于什么元素偏移？把它传给假定行步长为 2 的 kernel 会怎样？

<details>
<summary>参考答案</summary>

正确偏移为 `2 × 1 + 1 × 3 = 5`。错误的连续布局假设可能让部分位置碰巧正确，但整体索引不成立，例如 `[0,1]` 应读偏移 3，而不是偏移 1。

</details>
