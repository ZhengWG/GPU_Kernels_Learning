# 浮点数与误差：数学相等不保证逐位相同

**浮点数只能保留有限信息，每次运算都可能舍入。**

```text
原理示意：只保留有限精度时

(大数 + 小数) - 大数 → 小数可能在第一步丢失
大数 + (小数 - 大数) → 舍入发生的位置不同

改变求和分组 → 改变舍入过程 → 结果可能略有不同
```

GPU 归约经常改变加法顺序。乘加合并成一条指令时，也可能与先乘后加的舍入次数不同。因此 CPU 与 GPU、不同分块的 kernel 不一定逐位相同。[NVIDIA 浮点说明](https://docs.nvidia.com/cuda/floating-point/index.html)

| 类型 | 存储字节 | 初学时需要记住 |
| --- | --- | --- |
| FP32 | 4 | 常用参考精度，但仍有舍入误差 |
| FP16 | 2 | 比 FP32 更容易发生范围溢出和精度损失 |
| BF16 | 2 | 指数位数与 FP32 相同，但保留的有效数字更少 |

输入类型、乘法方式、累加类型、输出类型需要分别说明。例如输入是 16 位，不代表累加也必须是 16 位。Tensor Core 是专门处理矩阵运算的硬件，不能仅由输出 dtype 推断实际计算方式。

## 怎样比较结果

常见条件是：

```text
abs(结果 - 参考) <= atol + rtol * abs(参考)
```

`atol` 限制接近零时的绝对误差；`rtol` 限制相对于参考值的误差。它们取决于数据类型、求和长度与算法，不应全仓库随意用一个值。

检查最大误差及失败位置，也检查 NaN 和无穷值。高精度的小尺寸参考有助于发现索引错误；随机输入之外，还需大小混合、重复值和数值边界。归约结果不稳定时，先排除读写冲突，再讨论舍入。

## 自测

两个版本结果只差一点，是否可以直接放宽误差标准？

<details>
<summary>参考答案</summary>

不可以。先确认索引、掩码、同步、计算类型正确，再用更高精度参考判断误差来源。错误实现也可能只在少数输入上产生小差异。

</details>
